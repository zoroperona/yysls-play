# 通用开发流程

依据当前开发规范整理，更新于 2026-10-09。真实 Boss 案例和项目身份信息不随模板发布。已有可复用代码与待实现接口严格区分，见 [模块参考](shared-reference.md)。

## 开发顺序

1. 记录分支、基线 SHA、未提交文件、范围、资料覆盖边界。
2. 复制 [制作单](templates/boss-production.md) 和 [时间轴](templates/boss-timeline.md)。记录录像来源、战斗零点、采样位置、剪辑/倍速/缺段；公开记录使用证据 ID，不放私有链接或本机路径。
3. 每轮独立 eventId，分别填写机制描述、视觉、玩家动作、AI 分工、音频、全流程 UI、前置、失败、清理和验收。标记用户确认、录像确认、OCR 待核、演练假设、未知；未知不能由代码暗自决定。
4. 先实现预警→输入→判定→反馈→重试/继续的单机制链，再接完整时间轴。AI 不代替玩家必做动作，所有合法玩家格位必须且能够完成任务。
5. 规则卡、配置/判定、提示、测试同步；文案与显示从实际判定状态取得，不维护另一套数值。
6. 进行自动测试、构建与实际输入测试；反馈回写文档。在独立 worktree 验证固定提交，避免依赖其他工作区文件。
7. 同步三分支，记录推送与平台发布状态。线上检查版本、子路径、资源、HTTPS 和实际操作。

## 阵容和输入

支持五人单列单治疗、十人两列双治疗；每队第五格治疗，仅一个玩家，格位不随倒地/复活变化。默认名单中性化，真实名单由私有配置提供。成员 ID 不能使用显示名。

PC：WASD 移动、按住 Q 输出、逐次 E 卸势、Shift 闪避、Esc 暂停、左右键切实际轮次。F/G 仅在机制确有对应能力时启用。手机：左侧浮动摇杆，右侧对应语义按钮；PC/手机/微信使用同一玩法与判定。

摇杆以首次触点为中心，死区后移动，斜向不加速；移动/持续输出/逐次动作支持多指。键盘 repeat 不能形成连点。松手、取消、丢失捕获、失焦、后台、暂停、切机制、转屏和终态清输入。弹窗不透传输入。

## 时钟、血量和状态迁移

固定 1/60 秒模拟步长。空档默认 3×、机制 1×；移动、冷却、治疗和救援使用实际游戏时间，暂停冻结所有计时，恢复不追赶后台时间。默认救援 5 次、等待 5 秒、恢复 30/100 血，治疗自活不限次数；允许明确记录并配置差异。

所有机制节点正常进入、章节初始化、切换、重试及组合子节点均一次性强制赋值：`hp = round(maxHp * ratio)`，活动节点至少 1 血。低于节点也补至节点，不能仅下调或每帧锁血。独立护盾/小怪血量分别记录。比例必须来自可辨认证据或明确的演练假设，不用 DPS/时长反推，未知不能静默设满血。

| 操作 | 场景、时间、资源 |
| --- | --- |
| 暂停/日志 | 冻结并清输入，保留状态，显式继续 |
| 新章节 | 回准备页，创建新局，目标前默认 4 秒 |
| 前后切机制 | 按唯一轮次定位；保留团队 HP、倒地、救援及进度；清临时状态，重建目标前置，应用血量节点 |
| 失败重试 | 返回失败轮次前导；保留分组，满血、重置救援，重建前置和节点 |
| 个人倒地 | 禁止操作，AI 和救援继续，不等于团灭 |
| 硬性团灭 | 全员归零，停止治疗/救援，明确原因 |
| 胜利 | 冻结，仅播放一次胜利表现，然后结果弹窗 |
| 从头再来 | 清章节，同分组建立完整新局 |
| 查看战场 | 关闭结果弹窗，保持终态 |
| 资料截止 | 显示演练结束/后续待补，不冒充击杀胜利 |

正常推进保留按规则应持续的效果；手动入口执行退出旧轮次→清输入/临时状态→重建目标身份/层数/站位→重建时间队列/血量→刷新 HUD。失败定位不能退回同名技能第一轮。

## 素材、声音与 UI

世界坐标明确单位；渲染、点击逆变换、判定、AI 共用坐标，文字与按钮用 CSS px。玩家普攻使用 shared/attack-effects.js，AI 普攻只结算伤害，不画普攻弹道；机制弹道独立。头像、名字、血条、状态分层，不用装饰遮挡判定。

素材记录来源、授权、主体锚点、透明留白、尺寸、体积、路径和失败兜底。仓库不附带原项目素材。音频按 BGM/技能/交互/语音/胜负分类，记录触发、停止、循环、并发、音量和生命周期；未要求音效/语音不自动增加。

BGM 默认媒体时间独立推进，50% 音量，首尾各 5 秒淡入淡出；暂停续播，重开/失败重试重置，终态停止。图片解码就绪，音乐优先等待最多 15 秒后允许入场，90 秒下载超时可重试；成功资源保留。mountLoading 需要胜利图片和 BGM 对象，不能把它当作无参数加载器。

UI 按 [总规范](ui/README.md) 覆盖加载、准备、战斗、暂停、音乐、提示、胜负和日志。功能跨端同义。开始不自动请求原生全屏；手机竖屏暂停，不增加底部转屏文案。

## 验收与交接

自动检查覆盖成功、失败、边界、随机目标、连续机制、重复轮次、血量高低两侧入口、残留清理、暂停/重试。实际操作必须从准备页开始，不能用直接改状态或自动通关代替。

设备矩阵：PC 1440×900，横屏 844×390、667×375、568×320，平板、竖屏过渡；Chromium、WebKit 与 iPhone Safari 实机分别记录。检查多指、长按、地址栏变化、安全区、后台恢复、首次资源失败、子路径和旧缓存。模拟器不等于真机。

交接记录：源码 SHA、变更接口与调用方、已提交/未提交、命令结果、设备、步骤、证据、失败/未测项、负责人和下一步。需求确认、实现完成、实测通过、推送和发布是不同状态。
